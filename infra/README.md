# Infrastructure: the gateway installers

This directory builds the optional **cloud side** of NSA: a hardened gateway (Ollama + LiteLLM) on a fresh Debian/Ubuntu machine. Two editions produce the same result.

> Fresh machine and want the exact commands in order? Follow **[RUNBOOK.md](RUNBOOK.md)**.
> Want the design, sizing and operating notes? See **[../docs/DEPLOYMENT.md](../docs/DEPLOYMENT.md)**.

## Choose an edition

| | **Shell** (`shell/`) | **Ansible** (`ansible/`) |
|---|---|---|
| Needs | bash, curl, root | `ansible-core` where you run it; Python on the target; SSH or a local connection |
| Settings | `infra/infra.env` | `ansible/group_vars/all.yml` (+ `ansible-vault`) |
| Preview | `--dry-run` | `--check --diff` |
| Several hosts | no | yes (inventory groups, `--limit`, tags) |
| Without systemd | `nohup` fallback (no restart on reboot) | not supported |
| Extras | `preflight`, `verify` | opt-in `hardening` role (default-deny firewall, automatic updates) |
| Verified | real machines (fresh install, re-run, reboot, rebuild) | lint, syntax-check and render-comparison only; **not yet executed against a host** |

Both render byte-identical `litellm.yaml`, `nsa-gateway.service` and Ollama override files.

## What gets built

```
 client (your workstation)         gateway host
 ┌───────────┐  tunnel / tailnet   ┌──────────────────────────────────────────┐
 │ nsa CLI   │ ──────────────────▶ │ LiteLLM  :4000   (master key required)   │
 └───────────┘   OpenAI /v1 API    │     └─▶ Ollama 127.0.0.1:11434 (private) │
                                   │ models: NSA_MODEL_MAIN/FAST_CLOUD        │
                                   └──────────────────────────────────────────┘
```

- **Ollama** listens on localhost only; one model and one request at a time.
- **LiteLLM** is the only network-facing service. It binds to the Tailscale IP (`NSA_EXPOSE=tailscale`) or `127.0.0.1` (`NSA_EXPOSE=localhost`, reached by SSH tunnel). Never `0.0.0.0`.
- It runs as the unprivileged `nsa` user from a **read-only** virtualenv under `ProtectSystem=strict`, `NoNewPrivileges`, `PrivateTmp`.
- The master key is generated once into `/etc/nsa/gateway.env` (`0640 root:nsa`) and never regenerated by a re-run.
- The host holds no state worth keeping. To rebuild, delete it and run the installer on a new one.

## Shell edition

```bash
cd infra
./shell/bootstrap.sh preflight                       # read-only: can this machine host the gateway?
cp infra.env.example infra.env                       # then edit (see ../docs/CONFIGURATION.md)
sudo -E ./shell/bootstrap.sh server --dry-run        # preview, changes nothing
sudo -E ./shell/bootstrap.sh server                  # build; ends with a smoke test
sudo ./shell/bootstrap.sh verify                     # re-run the smoke test any time
```

On the workstation: `./shell/bootstrap.sh client --cloud-url http://<address>:4000/v1` installs the CLI and writes `.env`, or just use `nsa connect`.

Subcommands: `preflight`, `server`, `client`, `verify`. Options: `--vars FILE`, `--dry-run`, `--cloud-url`, `--cloud-key-file`.

**What `server` does, in order:** checks OS/arch/disk → installs base packages (waits for the apt lock) → creates the `nsa` user and directories → installs Tailscale from its signed apt repository (tailscale mode) → installs Ollama (prints the installer hash; repairs backend permissions) → configures and restarts Ollama → pulls the models (one log line per layer) → installs LiteLLM into `/opt/nsa/venv` → generates the key (first run only) and renders config and unit → starts the gateway and **waits** for it → runs the smoke test → prints the connection details and the versions to pin.

## Ansible edition

```bash
cd infra/ansible
python3 -m pip install ansible-core && ansible-galaxy collection install -r requirements.yml
cp inventory.example.ini inventory.ini               # add your host(s); `ansible_connection=local` runs on the box itself
ansible-playbook site.yml --check --diff --limit nsa_servers     # preview
ansible-playbook site.yml --limit nsa_servers                    # apply
ansible-playbook site.yml --tags ollama,gateway,verify           # just part of it
```

Roles: `common` (checks, packages, user), `tailscale`, `ollama`, `gateway`, `hardening` (opt-in), `verify`, and `nsa_client` (workstation). Secrets: `TAILSCALE_AUTHKEY` from the environment or `ansible-vault`.

## The smoke test: `scripts/verify.sh`

Used by both editions. It checks:

1. the gateway answers its liveness endpoint;
2. a request with **no key** and a request with a **wrong key** are both rejected (any non-2xx; LiteLLM without a database uses 500/400 instead of 401, and fails closed);
3. the correct key lists the expected models;
4. a real completion returns a short, non-empty answer (a long answer to a one-word request is reported as probable reasoning leakage).

## Settings that matter

| Setting | Default | Notes |
|---|---|---|
| `NSA_EXPOSE` | `tailscale` | `localhost` for the SSH-tunnel setup |
| `NSA_MODEL_MAIN_CLOUD`, `NSA_MODEL_FAST_CLOUD` | `qwen3:4b-instruct` | non-thinking; the same model for both aliases avoids reloads |
| `NSA_LITELLM_VERSION` | empty (latest, warned) | `1.108.1` validated; pin after your first good install |
| `NSA_OLLAMA_INSTALL_SHA256` | empty (warned) | enforce the installer hash printed in the log |
| `NSA_MIN_DISK_GB` | `10` | fresh install; a re-run needs 2 GB |

The complete list is in [../docs/CONFIGURATION.md](../docs/CONFIGURATION.md#4-installer-settings).

## Safety notes

- **Supply chain.** Defaults install the latest LiteLLM and an unverified Ollama installer; both editions warn. Tailscale comes from its signed apt repository. Pin and verify as above.
- **The host is a third party's machine.** The gateway key and anything you send there are visible to the provider. Sensitive agents stay local in the CLI and cloud prompts are redacted.
- **No public ports by design.** The Ansible `hardening` role adds a default-deny firewall that still allows SSH and the tailnet gateway port; it is opt-in so a first run cannot lock you out.
- **Authentication fails closed but looks odd.** LiteLLM without a database answers bad keys with HTTP 500/400 (and logs a traceback). Nothing is served. `nsa` and `verify.sh` recognise this. Clean 401s and per-client keys need LiteLLM's database mode, which is not part of this build.
- **GPU hosts.** Both editions make `/usr/local/lib/ollama` world-readable after installing Ollama; without that a root-only CUDA directory makes Ollama silently use the CPU.
- **First-boot apt lock.** Fresh VMs run automatic updates; the installers wait up to 5 minutes for the lock.
- **Rotating the key.** Delete `/etc/nsa/gateway.env`, re-run the installer, run `nsa connect` with the new key. *(Designed, not exercised.)*

See the [verification matrix](../docs/TESTING.md#4-infrastructure-verification-matrix).
